# LLM × 物理机制库：现状、实名 PDESR 对比与收敛曲线

> 数据：`Traffic_Flow_Bottleneck`（1D、单场），模型 `deepseek-v4-flash`（teamo 网关），
> 每条 100 个 LLM 样本。收敛图：[收敛对比.png](收敛对比.png)

## 0. 一句话结论

当前框架 = **原版 PDESR + 物理机制库 + LLM 动态参与**。在实名（prompt 告诉变量）条件下，
**让 LLM 依据变量自行设计机制库**之后，
Traffic 方程 100 样本达到 **MSE 4.90e-11** 并恢复出真骨架。

## 1. 框架：三层结构

| 层 | 是什么 | 谁定 | 是否可变 |
|---|---|---|---|
| 元语法 | 机制允许怎么拼：`D / S / MUL / DIV / POW / ABS / X / T / coord` + 算术 | 人为，固定 | 不可变 |
| 机制库 | 这个问题的物理算子集合（守恒通量、相对梯度扩散、tanh 瓶颈…） | LLM（设计或生长） | 每题不同、随 run 长大 |
| 数据闸门 + 搜索 | 机制必须在数据上实测；方程仍由搜索从数据里找 | 数据 | 每次运行 |

元语法必须“充分”，否则真项可能落在搜索空间之外。当前已做到：

* `+ − × ÷` 与 `POW / ABS` 自由使用；
* 坐标可参与运算（`X(0)`），因此 **`exp` 的指数可以是任意多项式、项数与次数自由**：
  `S(X(0) + k0*POW(X(0),2) + k1*POW(X(0),3), 'exp')`；
* 机制定义里也允许加减与除法，例如 `DIV(D(f1,axis,1), f1)`。

机制属于“物理”，原语属于“数学”：原语一次性给全（数学能力），机制按题由 LLM 设计（物理先验）。

## 2. 机制库怎么产生与长大

**设计步（配置 B，`10_LLM设计机制库`）**

1. 输入：变量身份 + 物理角色 + 域（与基线同源的实名描述）+ 原语清单；
2. 人为规定的结构规则：必须给出 scope / out_of_scope、2–4 个层级与优先级、搜索计划、
   禁用模式；每条机制必须是固定导数阶算子；
3. 校验：代数封闭 + 导数阶必须与定义一致；
4. 数据实测：能否在该问题上实例化出原子，以及 held-out 证据比值；
5. 冻结归档：`results/designed_library.json` + `results/mechanism_registry.json`。

**生长步（`08` / `09`）**

专家循环：提案 → 校验 → held-out 闸门（残差改善 ≥ 阈值）→ 升级入册 → 回灌提示与 grammar；
注册表跨 run 持久化，沙箱子进程通过 `PDE_GRAMMAR_REGISTRY` 重新加载新机制。

**与“完全自由”的区别**：LLM 决定的是范围与内容，不是语法。所有机制都被元语法约束成
固定算子，因此“真项在搜索空间之外”被结构性排除。

## 4. 骨架对比

### 4.1 五个方程的实名结果（我们本地复现，500 样本；括号内为论文报告值）

| 方程 | 真解 | 实名 PDESR 发现 | 本地 MSE（论文） | 状态 |
|---|---|---|---|---|
| Topography_Chemotaxis | `0.1u_xx − 0.5(u(1−u)cos x)_x + u(1−u)` | `∂_x(p0·cos(x)·u·(1−u/p2)) + p1·u_xx + u(1−u/p2)` | 7.39e-11（7.6e-5，≈） | 完全对（含显式 cos x） |
| Morphogenesis | `0.1u_xx − u/(0.5+u) + exp(−x²)` | `p0·u_xx − p1·u/(p2+u) + exp(−x²/2σ²)` | 7.05e-11（1.2e-10，⋆） | 完全对 |
| Forced_Swift_Hohenberg | `1.5exp(−0.1x²)u − 2u_xx − u_xxxx − u³ + u⁵` | `p0·u_xxxx + p1·u_xx + p2·u³ − p3·u⁵ + p4·exp(−x²/p5)·u` | 1.90e-8（2.2e-4，≈） | 完全对（含 u⁵ 与乘性 Gaussian） |
| Traffic_Flow_Bottleneck | `−(u(1−u)(1−0.5tanh x))_x + 0.05(u_x/u)_x` | `−∂_x(u(1−u)(1+p2·tanh(x·p3))) + p0·∂_xx(u/(1+u)) + p1·u_xx` | 6.96e-7（1.6e-4，×） | 通量对；期待项形式不同 |
| Predator_Prey | `u_t=0.05u_xx+u(1−u−0.5v)`；`v_t=0.01v_xx−0.2(vu_x)_x+0.8v(u−1)` | u_t 完全一致；`v_t = p3v_xx + p4u_x + p5uv + p6v + p7∂_x(vu_x)` | 8.79e-8（4.4e-9，⋆） | 基本对；多一项 u_x |

论文自己的那次 Traffic 判为失败（×），Topography 用 `0.158u_x` 顶替了 cos(x) 调制。
我们本地这轮（deepseek-v4-flash、实名、500 样本）恢复得比论文报告更强。

### 4.2 Traffic 上“机制库”带来的差别

真解：`−(u(1−u)(1−0.5·tanh x))_x + 0.05·(u_x/u)_x`

08/09 的固定库从未写出 `(u_x/u)_x`——该算子不在库里。10 的设计步自己把它放进了范围：

```
level 1 守恒/平衡 : conservative_advection(phi,psi,axis) = D(MUL(phi,psi),axis,1)
level 2 本构闭合 : relative_gradient_diffusion(f1,axis) = D(DIV(D(f1,axis,1),f1),axis,1)
                   exponential_flux(f1,axis)           = D(S(f1,'exp'),axis,1)
                   cubic_diffusion(f1,axis)            = D(MUL(POW(f1,2),D(f1,axis,1)),axis,1)
level 3 瓶颈调制 : bottleneck_advection_coefficient(f1,xaxis)
                   = D(MUL(f1, S(X(xaxis),'tanh')), axis, 1)
```

10 最终找到的方程（100 样本，MSE 4.90e-11，复杂度 18）：

```
f1_t = p0·∂[u(1−u)]/∂x + p1·∂[(u_x/u)]/∂x + p2·∂[u(1−u)·tanh(x)]/∂x
```

将真解展开：`−∂[u(1−u)]/∂x + 0.5·∂[u(1−u)tanh x]/∂x + 0.05·∂[(u_x/u)]/∂x` —— 逐项一致，
系数由 `params` 吸收。
