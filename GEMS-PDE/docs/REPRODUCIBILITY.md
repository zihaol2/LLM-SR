# 复现、来源和资源统计

## 三种运行含义

1. `audit-published`：读取打包快照，核对哈希并重新评价；可选 `--check-mse` 用保存系数重算残差。零 API，无新搜索，不把这当成一次独立实验。
2. `refine --source-dir artifacts/published/proposed42`：从历史选中状态重新运行完整邻域联合拟合；零 API，有完整数值计算。
3. `search / baseline / run`：新 API 运行，依赖用户的端点、模型和配额。未保证服务端仍提供相同模型修订版本。




## 打包改动及其影响

- 消除历史目录动态导入和绝对路径，数据/先验改为可配置任务表。
- 把密钥从读取父项目 .env 改为本包环境变量/本包 .env。
- API 缓存绑定完整非密钥请求；恢复绑定代码、设置、数据、先验与数值环境。
- 记录所有新 HTTP 尝试的状态与可获得 usage；校验 LLM JSON 基本结构。
- 固定原 `list(set(...))` 候选顺序为排序顺序，提高新运行的可复现性。
- 对不符合历史数值假设的数据（非均匀空间网格、形状不符、时间样本不足等）明确报错。
- 原 Pareto 实现只适配包内导入和标准 logging，移除重型运行环境配置依赖；未替换 Pareto 更新/提示算法。

拟合残差、默认 80/32/10、复杂度、0.1 权重、短/完整拟合预算、默认构造族、二倍接受门槛及四轮上限均保持。由于固定候选顺序、API 采样和模型修订等因素，新鲜搜索不保证逐位等于历史轨迹。历史快照原样保留，不能把其数值宣称为整理后新跑得到。

两种方法没有匹配 token 或数值搜索预算，不宣称总计算成本更低。校正登记至最终冻结历史本机墙钟约 1686.66 秒、两个并行任务进程，非 CPU 核时，非整条方法耗时。

## 冻结后 Jaccard

评分按微分和加法展开后的结构项集合计算；保留输出标签、变量、函数、幂和导数阶数；忽略非零数值系数与函数内部数值尺度；绝对系数不超过 1e-10 的项按零处理。五题分别评分，另报告五题算术平均和合并交集/合并并集。

参考方程物理上单独存储，只由显式评价命令解析。程序隔离不意味着研究者从未看过这五题：它们是经过多轮开发的任务集。要证明泛化需固定方法后做未见方程、独立初值、噪声、网格与预算匹配的实验。
