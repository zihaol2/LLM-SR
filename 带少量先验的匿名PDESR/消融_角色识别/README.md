# 消融：角色识别靠哪一路证据？

同一个问题（"f1 到底是什么"）、同一个模型，三种证据配置，**三个问题各跑一遍**：

| 条件 | 给的东西 |
|---|---|
| `cond1` | 只给统计信息 |
| `cond2` | 统计信息 + 真值方程 |
| `cond3` | 统计信息 + 真值方程 + 母体候选 ← 现在 pipeline 的做法 |

## 设定

- 方程一律当**真值**用（假设搜索已经找到了），所以这里隔离出来的就是角色识别这一步。
- 三个问题的真值（取自项目自己的 `TRUTH_EQUATION` / `roles_summary.md`）：

| 问题 | 真值方程 | f1 真值角色 |
|---|---|---|
| traffic | `u_t = -d/dx[u(1-u)(1-0.5 tanh x)] + 0.05 d/dx(u_x/u)` | 车流密度 |
| Forced Swift–Hohenberg | `u_t = 1.5 exp(-0.1x²)u - 2u_xx - u_xxxx - u³ + u⁵` | 序参量（图样振幅） |
| Topography Chemotaxis | `u_t = 0.1 u_xx - 0.5 (u(1-u) cos x)_x + u(1-u)` | 种群密度 |

## 公平性怎么保证

每道题内部，三个 prompt 由**同一个模板**拼出来，脚本先自检、不通过就不跑：

1. 头部说明逐字节相同
2. **统计信息块逐字节相同**（同一题的三个条件之间）
3. 结尾 `### YOUR TASK` 与 JSON 输出格式逐字节相同

差别只在中间插了哪几个证据块。把三题放在一起比时还有个附加控制：**同一份统计计算计划**
（`../results_design/statistics_plan.json` 里的 12 条统计）套用到三个数据集上，
所以"统计信息"这一路的强度是可比的。

统计块 = 12 行实测统计 + 由统计读出的宏观角色（`role_only_prompt` 产生，不看先验）。
方程块 = 真值方程 + 系数。母体块 = 用 pipeline 的 `parents_prompt` 问出来的 6 个候选族
（prompt 里明确禁止给族名示例，实测 0 命中 traffic/road/vehicle/density/LWR 等词）。

## 怎么跑

```powershell
cd 消融_角色识别
python run_all.py evidence      # 生成三题的证据（统计读数 + 母体匹配）
python run_all.py run           # 3 条件 × 3 次 × 3 题
python score_and_plot.py        # 判分 + 出图
```

产出：`evidence/<题>/`（统计、方程、母体、真值）、`prompts/<题>/*.txt`（完整 prompt，
可自行 diff）、`ablation_all.json`（全部原始回答）、`对比_角色识别_三问题.png`。

## 结果

判分分两档：**命名正确**（真的说出了那个量）、**只对族**（族说对了，量还是一串备选）。

| | cond1 只统计 | cond2 +真值方程 | cond3 +方程+母体 |
|---|---|---|---|
| 命名正确 | **0 / 9** | **3 / 9** | **9 / 9** |
| 只对族 | 0 / 9 | 3 / 9 | 0 / 9 |
| 未命中 | 9 / 9 | 3 / 9 | 0 / 9 |

分题看：

| 问题 | cond1 | cond2 | cond3 |
|---|---|---|---|
| traffic（车流密度） | 0/3 —— 温度异常、松弛变量、海面高度 | 0/3 —— 种群密度、涡量、种群密度 | **3/3 车流密度**（medium/high/high） |
| Forced Swift–Hohenberg（序参量） | 0/3 —— 温度/示踪剂浓度 ×3 | **族全对**（3/3 提到 Swift–Hohenberg / Ginzburg–Landau），但量是"浓度、温度异常或振幅"这种并列 | **3/3 序参量/图样振幅**（含"局域泵浦的 SH"） |
| Chemotaxis（种群密度） | 0/3 —— 温度、盐度 | **3/3 种群密度/生物量**（母体给 Fisher-KPP 类） | 3/3 种群密度（high/high/medium） |

![三问题三角色条件对比](./对比_角色识别_三问题.png)

## 读出来的三件事

**1. 统计量从来不提供名字（0/9，三个问题无一例外）。**
同一套统计特征在不同问题上被读成温度、盐度、浓度、示踪剂——它们是"非负/低频/与自身负相关
的标量场"这一层描述，跨学科不可分。

**2. 方程能定死结构，但只有一个问题顺便把名字也带出来了。**
- 化学趋化那条 `0.1u_xx - 0.5(u(1-u)cos x)_x + u(1-u)`：扩散 + 逻辑斯蒂增长 + 密度依赖输运
  这套组合在文献里几乎只出现在种群模型里，所以 cond2 直接给出"种群密度"（3/3）。
- Swift–Hohenberg 那条：cond2 **三答三中把族认对了**（SH / 实 Ginzburg–Landau），
  可它给出的量仍然是"标量场（例如浓度、温度异常或振幅）"——**知道是图样方程，却不肯说
  那个量叫序参量**。
- 交通那条：cond2 三次分别给出种群密度、涡量、种群密度，**族和量都没中**。

**3. 加上母体这一步之后，9/9 全部落到真值命名，而且置信度普遍升高。**
而且这一步是**可验证**的，不是"模型说是就是"：母体的 canonical form 代入它的符号约定后，
恰好就是发现的那条方程（交通那条已经在上一版做过这个恒等式核对）。

## 结论

**命名能力来自"方程 → 经典母体"这一跳。** 统计量只能把问题限定到"某个非负标量场的输运"；
方程把结构定死，但结构相同的族在多个学科里长得一样，模型会保守地把量写成并列备选；
只有把方程映射回经典母体、再从母体的符号表里读名字，才能确定下来。

三题之间的差异也有信息量：**母体这一步的边际贡献，取决于该族的"量名"在学科约定里有多抢眼**。
化学趋化的方程本身就叫 Fisher-KPP，名字几乎写在方程上；交通需要母体来点名；
Swift–Hohenberg 最典型——族认得，量名不敢说，母体一给就定了。

## 局限（必须写进论文）

1. **母体是模型自己给的**。`parents_prompt` 里没有任何族名示例、也没有数据集名（已扫描确认），
   但同一个模型既提候选又读符号表，属于闭环。缓解：term mapping 可机械核对（恒等式），
   且交通那条用干净数学式做过独立对照，照样召回 LWR。
2. **每条件 3 次**，无种子控制。分离很干净（0/9 → 3/9 → 9/9），但重复次数偏少。
3. **判分是人工读的**（规则写在 `score_and_plot.py` 顶部的 `VERDICT` 字典里，可对照
   `ablation_all.json` 复核），"只对族"和"命名正确"的界线是我划的。
4. 三个条件长度不等、新证据块总在末尾（近因优势）——和上一个搜索消融同样的限制。
